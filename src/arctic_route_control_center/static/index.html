使用说明与运行目录

快速开始

  1. 启动 Linux AppImage 或 Windows EXE。程序会保留后端命令台并打开本机浏览器；默认地址为 http://127.0.0.1:8130/。
  2. 先在“船舶与场景”检查只读 Contracts，再到“设置”分别填写 Copernicus Marine 的 .env.copernicus 和 CDS/CARRA 的 .cdsapirc 外部绝对路径。
  3. 在“A 数据下载”准备数据；在“制品构建”依次生成 A Bundle/RunContext、运行 Orchestrator、发布 Viewer 包。新包先进入 artifacts/inbox。
  4. 在“制品库”确认校验通过并提升到 artifacts/ready，然后点击顶部“打开 Replay Viewer”。外部 ready 制品可在运行时接收，不需要重新打包；同名制品也会按来源分别显示。
  5. 停止服务请按 Ctrl+C 或关闭命令台；浏览器页面本身不是后端进程。

平台与启动参数

Linux / AppImage

默认运行数据：

${XDG_DATA_HOME:-~/.local/share}/arctic-route-control-center/

无 FUSE 的环境可使用：

./release/Arctic_Route_Control_Center-x86_64.AppImage \
  --appimage-extract-and-run

正式凭据文件建议置于程序、仓库和数据目录之外，并设置为当前用户可读写（例如 chmod 600）。

Windows / EXE

默认运行数据：

%LOCALAPPDATA%\ArcticRouteControlCenter\

EXE 是 onedir 发行物，必须保留整个 arctic-route-control-center 目录；双击 EXE 会保留命令台并打开本机浏览器。

Windows 凭据文件应限制为当前用户可读，并置于 EXE、仓库和数据目录之外。

两平台都可以用 --data-root <目录> 或 ARCTIC_ROUTE_DATA_ROOT 覆盖默认数据根，也可以用 --host、--port 调整本地监听参数；--host 仅接受 127.0.0.1、localhost 或 ::1，服务只监听回环地址。

运行目录结构

arctic-route-control-center/
├── config/
│   └── settings.json              # 两个外部凭据文件的路径
├── data/
│   └── work-package-a/            # A 下载数据、manifest、缓存数据
├── artifacts/
│   ├── inbox/                     # 待审核制品
│   ├── ready/                     # 审核通过、可供 Viewer 使用的制品
│   └── invalid/                   # 校验失败制品
├── run/
│   ├── control-center.json        # 当前后端 PID、端口（如有）
│   └── jobs/<job-id>/             # 任务输出和摘要
├── logs/                          # 后端和任务日志
└── cache/                         # 下载缓存

Linux 默认根目录为 ${XDG_DATA_HOME:-~/.local/share}/arctic-route-control-center；Windows 默认根目录为 %LOCALAPPDATA%\ArcticRouteControlCenter。界面“运行总览”中的实际路径由后端返回，是排查覆盖参数后的准确信息。

名称用途平台 / 时机

不要把凭据内容写入环境变量、仓库、AppImage/EXE 或 Viewer 制品。设置页只保存两个外部文件路径：Marine 任务使用 .env.copernicus，CARRA 任务使用 .cdsapirc，二者不可混用。

常用接口与排查

  • 健康检查：/api/health；目录与版本：/api/catalog；设置：/api/settings；制品扫描：/api/artifacts。
  • Viewer 入口：/viewer/。制品必须通过 Schema、身份、checksum、PUBLISHED、路线数量和 formal motion 等校验，失败会保持不可展示。
  • 任务失败先看“任务与日志”和 run/jobs/<job-id>；不要手工修改制品 JSON、复制凭据或删除 inbox、ready、invalid 来绕过校验。
  • 这是本地工程研究与可重复回放控制面，不代表实船标定、导航认证或适航结论；D Viewer 只展示已发布制品。
